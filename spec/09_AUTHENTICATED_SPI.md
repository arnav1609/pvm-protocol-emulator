# Authenticated SPI v1 — implementation contract

**Actors.** IDs 1–10 are employees; 11 is the head. ID zero and 12–255 reject. The chip and a trusted provisioning service share a device-specific 32-byte master. Employee i receives only KMAC256(master, device_id || u8(i), 256, "PVM-KEY1"). Authenticated operations use that employee key. A public employee ID and a static tag alone cannot establish freshness. The signer constructs frames from the approved canonical image. For START it requires a new user confirmation displaying device and image root; unloading credentials from the shared terminal is part of that trust boundary.

**Transport.** Existing SPI mode 0, MSB first, SCK at most core clock/16. One frame per CS assertion. Use 0x9F for existing PVM ID, 0xA0 for SUBMIT, 0xA1 for INFO and 0xA2 for SAFE_READ. No legacy 0x02 or 0x03 path in the secure top. Capture the complete bounded SUBMIT, recognize exact bit length at CS rise, then verify and emit. Host polls INFO between commands. Never require an SPI slave to stretch SCK. Buffer only the bounded payload/tag/required fields or implement an equivalent streaming capture with proven full-rate capacity; a full-frame scratch array must be counted in synthesis. Ignore submissions while BUSY. Credential or freshness source unavailable means LOCKED with no writes.

**SUBMIT** = A0 || body || tag32. Body = version u8 (=1), operation u8, identity u8, device ID 8 bytes, session challenge 16 bytes, sequence u32, image root 32 bytes, payload length u8, payload bytes. All protocol integers are big-endian. The KMAC message is the exact body and customization is ASCII PVM-CMD1. Never include a terminating zero in a customization string. Check length, trailing bits, ID, device, active challenge, owner policy, expected sequence and tag before issuing any bus action. In-flight commands are indivisible to other host commands; hardware reset overrides them. Fixed-size metadata received on the wire can be compared to retained fields. The maximum frame is 153 bytes. Sequence 0 opens; accepted requests advance once; prohibit wrap. Return the last committed sequence through INFO to resolve a lost acknowledgement.

**Image commitment.** The original proposal used a flat SHA3 digest. This blueprint uses a SHA3 hash chain so the same permutation state can finish a chunk tag and then verify its image link without preserving a second live 1,600-bit hashing context. The image root remains a 32-byte identifier bound to OPEN and START. Each record is address u16 followed by data u8. Take exactly the frozen builder's ordered writes. Break into consecutive groups of eight records, except the final group may be shorter. meta = chunk_count u16 || expected_crc u16 || preload_length u8 || 0–4 preload bytes. terminal = SHA3-256(ASCII PVM-END1 || meta). Working backwards, link[i] = SHA3-256(ASCII PVM-BLK1 || index u16 || record_count u8 || record_bytes || link[i+1]); terminal is link[count]. Root is link[0]. Stage 1 vectors are normative examples. Byte order on the PVM register bus remains low byte first for multi-byte values.

| op | Who / state | Payload and committed effect |
|---|---|---|
| 01 OPEN | Any enrolled ID, unowned and stopped, seq 0 | meta. Require 1–255 chunks and valid preload length. Latch owner, root, count, expected CRC, preload and cursor=root. Issue HALT then CLR_IMEM. Enter LOAD; discard all previous authorization. |
| 02 CHUNK | Owner, LOAD | 1–8 complete records plus next 32-byte link. Check KMAC and current link before any write. Validate every address/mask/order in the whole chunk first. Require increasing valid IMEM word pairs (low then high), then each CONFIG_ADDRESSES byte exactly once in builder order and finally IMAGE_VER. Track order across chunks; reject reserved/control/FIFO/CRC addresses. Track byte count, no wrap or alias. Emit one byte write per beat, then commit next link and sequence. Abort to stopped/reload-required on any internal bus rejection. |
| 03 FINISH | Owner, LOAD | Empty. Require received count, terminal hash, canonical completion, and CRC_CALC == expected_crc. Write CRC_EXPECT low/high at 0F08/09, request VALIDATE via CTRL=02, wait for READY and CRC_OK, verify IMAGE_ID versus expected CRC and image version, then preload 0–4 bytes to 0F10. Publish READY only after preload completes. On fault, suppress ENABLE and require cancel/fresh load. |
| 04 START | Owner, authenticated READY | Empty. Confirm digest/root, sequence and PVM READY. Issue a single CTRL=03. Retain ownership until cancel/close even if the engine reaches DONE/FAULT. No auto-start. |
| 05 CANCEL/CLOSE | Owner or head, owned session; serialize behind in-flight work | Empty. Use active root, challenge and next sequence with the caller's own key. Issue HALT, discard pending authorization, keys and cached data, retire challenge. Head must separately OPEN a fresh session to replace a load. |
| 06 TX_PUSH | Owner, RUN | 1–4 data bytes. Require enough free TX slots before any push. Write 0F10 once per byte. Insufficient space returns retryable status without committing sequence or writing. |
| 07 RX_POP | Owner, RUN/DONE/FAULT | One count byte 1–4. Require enough RX bytes first. Read 0F11, wait one bus cycle for data, capture returned byte then assert bus_rack exactly once per byte. Cache result with accepted sequence for repeat reads after a lost acknowledgement. |
| 08 CLEAR_FLAGS | Owner, RUN/DONE/FAULT | Empty. Only CTRL=06. HALT, CLR_IMEM, VALIDATE and ENABLE are internal sequences defined above. |

**Readback.** INFO = A1, one dummy byte, then response: v1 u8, phase u8 (0 LOCKED, 1 LOAD, 2 READY, 3 RUN/owned, 4 reload-required), busy u8, result u8 (0 OK, 1 reject, 2 retry, 3 validation fault, 4 trust unavailable), owner u8, device ID 8, challenge 16, next_seq u32, last_committed_seq u32 (FFFFFFFF means none), active root 32 (zero while unowned), rx_result_len u8, rx_result padded to 4 bytes. Snapshot at frame start. Public readback is acceptable for this integrity-only prototype. Reject or discard empty/short frames without modifying ownership; reading INFO consumes nothing. SAFE_READ = A2, address u16, one dummy, one response byte. Permit only STATUS/FAULT/FLAGS/PC/FIFO_STAT, committed image ID and read-only monitor evidence per spec 03. Return zero for other addresses; never auto-increment into RXDATA or generate bus_rack. Public polling cannot starve an accepted operation.

**Reset and trust.** Reset the guard with the same synchronized core reset; invalidate session and command buffers and mask bus strobes through reset. Secure boot must bind the trust source to this device and establish a new challenge after reset or session retirement. Issue a challenge without reserving the chip, keep it stable until consumed/retired, and prohibit challenge reuse. After reset no start from retained bytes. The TT wrapper currently ignores ena. Check the actual platform deselection/clock/reset behavior; if a deselection is supposed to revoke a session, explicitly wire and test revocation with safe stopped recovery. Never derive freshness from PVM's timestamp, a reset-to-zero counter alone or arbitrary SPI input. Fail closed until a trusted secret and freshness source are available. External reset/power interruption can still stop the machine.
